# AI Agent 核心概念

> 配套学习路线的 Agent 模块笔记。与 `prompt-engineering.md` 互为上下游：
> **Prompt 是单次交互的语言技巧，Agent 是围绕 LLM 搭的自主循环系统。**

---

## 1. 什么是 AI Agent

一句话：**Agent = LLM（大脑）+ 工具（手脚）+ 记忆（笔记本）+ 目标驱动的循环（意志）。**

和普通 LLM 调用的差别：

- 普通调用：**一问一答**，用户问什么答什么。
- Agent：用户给一个**目标**，它自己拆任务、自己调工具、自己看结果、自己决定下一步，直到完成或放弃。

最小化实现可以用这样一个循环概括：

```
目标 → LLM 思考下一步 → 调用工具 → 观察结果 → 再思考 → ... → 交付
```

这个循环就是大名鼎鼎的 **ReAct 模式**（Reason + Act）的核心。

---

## 2. Agent 的四大核心能力

这四者缺一不可，合起来构成完整的"智能体闭环"：

```
   ┌─ 感知 ──→ 推理 ──→ 决策 ──→ 执行 ─┐
   │                                     │
   └──────────← 反馈 ←───────────────────┘
```

### 2.1 感知（Perception）

**获取外部信息的能力。**

| 渠道 | 举例 |
| --- | --- |
| 用户输入 | 文字、语音、图像、上传文件 |
| 主动检索 | RAG 检索向量库、调搜索引擎、查数据库 |
| 外部事件 | Webhook、定时触发、MCP 通知、消息队列 |
| 工具返回 | 上一次工具调用的结果（这是最重要的一种） |

落到实现上，感知层就是**「塞进 LLM 上下文的那段文字」**——文档片段、API JSON、OCR 结果、错误栈都算。

### 2.2 推理（Reasoning）

**基于感知到的信息做思考和判断。** LLM 最擅长的部分。

典型推理动作：

- **任务拆解**：把"写一个博客后台"拆成建表 / 写接口 / 写前端
- **因果推断**：这个报错是什么导致的
- **规划**：下一步该调哪个工具、参数应该填什么
- **评估**：当前信息够不够下结论，要不要继续查

实现手法：**CoT**、**ReAct**、**Plan-and-Execute**、**Tree of Thoughts**（见 `prompt-engineering.md`）。

### 2.3 决策（Decision Making）

**在多个可能动作中选一个执行。** 推理偏"想清楚"，决策偏"选哪个"。

需要决策的典型节点：

- 要不要调工具？调哪个？参数怎么填？
- 要不要向用户澄清？还是基于假设继续？
- 任务完成了吗，现在该停了吗？
- 遇到错误是**重试 / 换工具 / 回退上一步 / 放弃**？

工程落地上，决策通常借助 **Function Calling / Tool Choice**：模型输出结构化的
```json
{"tool": "search_web", "args": {"query": "..."}}
```
由外层框架去实际调用。

### 2.4 执行（Action）

**真正改变世界的那一步。**

- 调 API、写文件、跑 SQL、发邮件、点浏览器按钮……
- 执行结果会回流成下一轮的"感知"，闭环由此形成。

工程注意点：

- **危险操作必须有人类确认**（删库、打款、发公开内容）——这是红线。
- **失败要可重试、可回滚**，至少要幂等。
- **工具调用记录要审计**，Agent 做了什么必须可追溯。

## 3. Agent vs LLM 的区别

| 维度 | 纯 LLM 调用 | Agent |
| --- | --- | --- |
| **输入输出** | 一问一答，单轮 | 给**目标**，多轮自主推进 |
| **主动性** | 完全被动 | 自己决定下一步 |
| **工具** | 不用，或由调用方手动拼装 | 自己选工具、自己传参 |
| **记忆** | 只有上下文窗口 | 短期记忆 + 长期记忆（向量库 / 文件） |
| **终止条件** | 生成完就结束 | 模型判断"完成"或达到步数上限 |
| **错误处理** | 返回错误给调用方 | 自己观察、重试、换方案 |
| **典型调用方** | 开发者写的业务代码 | 用户用自然语言下达目标 |

> **核心认知**：Agent 不是一种"更强的模型"，而是**围绕 LLM 搭的一套自主循环系统**。
> 同一个 GPT-4，既可以当 LLM 用，也可以当 Agent 用，区别全在外面那层壳。

一个更直观的类比：

- LLM 像 ChatGPT 网页版——每一步都要你手把手带。
- Agent 像实习生——你说"帮我订明天去上海最便宜的机票"，它自己搜、自己比、自己下单，搞不定再来找你。

## 4. Agent 的应用场景

按"让 Agent 做什么"分四大类：

### 4.1 知识助理类
- **深度研究（Deep Research）**：给个话题，自己搜 N 个网页、交叉验证、出一份带引用的报告
- **企业知识问答**：接内部文档 / Wiki / 工单系统，回答"X 项目上次线是什么时候"这种跨库问题
- **合同 / 简历审查**：读完文档后给出结构化意见

### 4.2 编程助理类
- **Coding Agent**：Cursor、Claude Code、Codex——读代码、改代码、跑测试、提 PR
- **自动化 Debug**：看报错 → 定位文件 → 打日志 → 复跑 → 修复
- **Code Review Agent**：对着 PR 提意见，附上修改建议

### 4.3 办公自动化类
- **邮件 / 日程**：自动分类、回复常见问题、安排会议
- **客服机器人**：不止回答 FAQ，还能查订单、发退款、创建工单
- **数据分析**：自然语言 → SQL → 取数 → 画图 → 出结论

### 4.4 生活 / 工具类
- **Web Agent / RPA**：像人一样点网页、填表格、跨系统搬数据
- **智能家居**：协调温控、灯光、音乐根据情境联动
- **游戏 NPC**：有记忆、有目标、会规划的角色
